# Governance

Loupe is early and small, so this document is deliberately short. It
describes how the project is run today and how that changes as more
people arrive.

## Roles

**Contributors** are anyone who opens an issue or a pull request. No
paperwork beyond the DCO sign-off described in
[CONTRIBUTING.md](CONTRIBUTING.md).

**Maintainers** review and merge changes, cut releases, and set
direction. The current list is in [MAINTAINERS.md](MAINTAINERS.md).

## Decisions

Day to day, changes are made by pull request and merged by a maintainer.
Anything that changes the project's scope, licence, dependencies with
unusual licensing, or public interfaces should be an issue first, so the
discussion is findable later.

Decisions are made by lazy consensus: if nobody objects within a
reasonable window, the proposal carries. Where consensus fails, a simple
majority of maintainers decides.

## Becoming a maintainer

There is no quota and no fixed number of contributions. What we look for
is sustained, good judgement: reviews that catch real problems, changes
that come with tests, and a demonstrated interest in the project rather
than in one feature. Any maintainer may nominate a contributor; the
existing maintainers decide.

Maintainers who have not been active for six months move to emeritus.
This is administrative, not a judgement, and coming back is a matter of
asking.

## Licence and intellectual property

Loupe is Apache-2.0. Contributions are accepted under that licence via
DCO sign-off — contributors keep their copyright, and there is no CLA.

New dependencies should be under a permissive licence. Anything
copyleft needs discussion in an issue before it is added — unwinding a
dependency later is much harder than choosing differently now.
